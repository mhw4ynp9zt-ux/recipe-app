# コンダテ:「週プラン(朝食・昼食・夕食)」「買い物」「目標の目安」「食事の記録」「週の振り返り」「外食の写真」

ユーザーを責めずに、続けやすく栄養を整えるための機能群です(月額500円に見合う使い心地を目指したもの)。

## できること

| 機能 | 場所 | AI(有料) |
|---|---|---|
| 目標の目安(公的な基準表+自分で設定) | 設定タブ | 使わない |
| 食べたものの記録(保存レシピ/食材のグラム/かんたん入力) | 今日タブ | 使わない |
| 週の振り返り(良かった点→ヒント1つ→4週平均) | 今日タブ | 使わない |
| 週プラン(1週間の朝食・昼食・夕食。外食・作らない食事・差し替え・作り直し) | 週タブ | **「献立を考える」だけ使う(食事ごとに1回=最大3回)** |
| 週タブの日ごとのバランス(日付の帯→その日のゲージ。予定=薄い色、食べた=濃い色) | 週タブ | 使わない |
| 「食べた」記録(プランの食事に押す。今日タブの記録と同じ`meal_logs`に入る) | 週タブ | 使わない |
| 変更シート(保存レシピ/外食/作らない/決め直し)とレシピ詳細・編集(プラン内だけ変更、保存レシピは変えず、毎回サーバーで成分表から再計算) | 週タブ | 使わない |
| 買い物リスト(売り場ごと・家にあるもの別枠・チェック) | 週タブ | 使わない |
| 外食の写真から栄養を推定 | 今日タブ → 記録する → 写真 | **「推定する」だけ使う(1回)** |

「今日のバランス」「次の食事のおすすめ」は、週プランと週の振り返りがあるため、画面とAPIから外しました(2026年10月)。栄養の目安との比較は、週の振り返りと、週タブの日ごとのバランスにあります。

食べた記録は`meal_logs.recipe_id`に`plan:<プランID>:<日付>:<食事>`のキーで入り、外食・作らない・差し替え・編集に合わせて同期されます(DB変更なし)。AIにつながるのは従来どおり`POST /api/week/plan/:id/run`と`/api/meals/photo`だけです。

栄養の数字は、すべて成分表(`foods`)からコードで計算します。AIには食材とグラム数の推定だけをさせ、栄養値は出させません。

## 課金を起こさないための決まり(最重要)

- AIにつながるAPIは2つだけ: `POST /api/week/plan/:id/run`(週プラン)と `POST /api/meals/photo`(写真)。ほかは一切AIに届きません(`test/kondate-no-ai-cost_test.mjs` が import の到達先を確かめます)。
- AIへの通信は `functions/_lib/kondate-ai.js` の1か所だけ。再試行なし・タイムアウトあり。エラー本文は読まず、ログにも残しません(写真・キーが混ざらないように)。
- 画面は、AIを呼ぶ前に必ず「今月の残り回数」の確認を出し、タップしたときだけ呼びます(やめれば0回)。
- **朝食・昼食・夕食: 1回の実行で頼むのは「1つの食事」だけ**(最大7日ぶん・AIは1回)。3食ぶん頼むときは、画面が確認のあと、朝→昼→夕の順に1回ずつ呼びます(最大3回)。サーバーが続けて呼ぶことはなく、画面は「今月の残り回数まで」しか呼ばず、1回失敗したらそこで止めます(再試行なし)。できた食事は残り、失敗した回の回数だけ戻ります。
- 回数の上限は二重: ユーザーごとに月(週プラン12回・写真40回。`kondate-usage.js`)+ アプリ全体の1日(既存の `ai_usage_daily`)。判定と加算は1つのSQLで同時に行います。AIが失敗したら両方とも戻します。**週プランの回数は「食事1つの実行=1回」で数えるので、3食ぶんを作ると3回使います(夕食だけなら1回)。月12回のままだと、3食の週プランは月4回までです。** 回数を変えるときは `MONTHLY_CAPS.week` を直します。
- 実行中の二重押しはlease(取り合い防止)で409。埋める食事がないとき・食事の指定が不正なとき(400)はAIを呼ばず、回数も使いません。
- 写真は端末で縮小して送り、サーバーに保存しません。推定結果はユーザーが確認・修正してから「おおよそ」として記録します。
- 検証は偽のAIだけで行います。`test/_support.mjs` の見張り役は、x.ai への通信が試みられた時点でテストを失敗させます。

## 目標の目安の根拠と、公開前に確認してほしいこと

- 値は厚生労働省「日本人の食事摂取基準(2025年版)」の表をそのまま持っています(`functions/_lib/dri2025.js`、`test/targets_test.mjs` が値を固定)。独自の計算式は使わず、表にない組み合わせ(75歳以上の「高い」)は値を出しません。
- %エネルギーの目標量(たんぱく質・脂質・炭水化物)だけ、4・4・9 kcal/g でgに換算しています。
- **確認が必要**: エネルギー・たんぱく質は2つの資料で一致を確認済みですが、食物繊維・食塩相当量・炭水化物・目標とするBMIは付録表の1資料のみの確認です。公開前に、公式の報告書(PDF)と目視で照合してください。
- 妊娠中・授乳中・18歳未満・通院治療中の方は、自動の目安を使えません(手入力のみ+医師・管理栄養士への相談の案内)。

### アプリ独自の安全設定(基準表の値ではありません。確認してください)

| 設定 | 値 | 場所 |
|---|---|---|
| エネルギーの下限(自動・手入力とも) | 1,200kcal | `targets.js` `ENERGY_FLOOR_KCAL` |
| 「減らす」「増やす」の調整幅 | ±10% | `targets.js` `PURPOSE_ADJUST` |
| 基準より大きく低い手入力への相談のおすすめ | 基準の85%未満 | `targets.js` `LOW_ENERGY_RATIO` |
| BMIが目標範囲外のとき | 同じ向きの調整は選べない | `targets.js` |
| 範囲のない「目安」を「ちょうど良い」とする幅 | ±10% | `balance.js` `AIM_BAND` |
| AIに伝える1食ぶんの栄養の目安(1日の何割か) | 朝食25%・昼食30%・夕食35%(残りは間食など) | `week-plan.js` `SLOT_SHARE` |
| ヒントを出す基準 | 平均が下限の85%未満(増やす方向) | `balance.js` |

## やさしい言葉づかい

「不足」「足りない」「未達」「失敗」などを使わず、「まだ伸ばせます」「ちょうど良い」「整う」の言い方にそろえています(`kondate-messages.js`、`test/kondate-tone_test.mjs` が確かめます)。「あと◯g」のような差の数字は返しません(ゲージは位置と状態の言葉だけ)。数字を隠す設定もあります。連続日数などのストリーク表示はありません。

## データと記録

- 食事の記録は約5週間(35日)だけ持ち、記録のたびに古いものを消します。長期の履歴画面は作りません。
- 週プランは(ユーザー,週)ごとに1つ。今週と来週だけ作れます。作るときに、考える食事(朝食・昼食・夕食のうち1つ以上)を選び、食事ごとに「作る/外食/作らない」を決めます。今日のすでに過ぎた時間帯の食事は、はじめから「作らない」になっています。
- 朝食・昼食は、手早く作れる・材料と手順を短く(出力量=料金を抑える)AIに頼みます。別の食事の料理名は「最近つくった料理」としてAIに渡し、同じ料理が続かないようにします。
- 1週間の栄養の平均は、「決まっている食事の合計」を日ごとに出して、日数で平均します。
- 以前(夕食だけ)のプランも、そのまま夕食として読めます(DBの変更はありません。`week_plans.days` のJSONに `slot` が付くだけで、保存し直すときに新しい形になります)。

## 本番に出すときの手順(要承認)

(朝食・昼食・夕食の対応と「今日のバランス」の削除には、新しいDBの変更はありません。)

1. `db/migration-011-kondate.sql` をD1に適用(`CREATE TABLE IF NOT EXISTS` のみ。何度流しても安全。既存のデータには触れません)。適用前は、新しいAPIは503で「準備中」を返し、既存の機能は今までどおり動きます。
2. マージ → デプロイ。
3. 公式PDFでの値の照合(上記)と、安全設定の確認。
