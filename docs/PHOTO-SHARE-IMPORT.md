# 料理の写真・共有リンク・レシピの取り込み

保存済みレシピに「料理の写真」を付け、「共有リンク」で他の人に送り、リンク・レシピサイトのURL・貼り付けた文章から「取り込み」ます。
**この機能はAI(xAI・有料)を一切使いません。** 利用回数の消費も、AI設定の参照もありません。

## 使い方(画面)

| やりたいこと | 操作 |
|---|---|
| 写真を付ける | 保存済み → レシピをタップ → 「写真を追加」(カメラ/ライブラリから選ぶ)。付けると一覧のタイルにも出る。「写真を変更」「写真を削除」もここ |
| 共有する | 詳細シートの「共有」(ログイン中のみ)→ 共有メニューを開く / リンクをコピー / X / LINE。「共有をやめる」でリンクは見られなくなる |
| 共有されたレシピを見る・取り込む | 共有リンクを開く(ログイン不要)→ 「自分の保存済みに入れる」。未ログインならこの端末に保存される |
| 取り込む | 保存済み画面右上の「取り込む」ボタン → 「リンク(URL)」か「テキスト」 |

### 取り込みの流れ
- **共有リンク**(このアプリの `…/?share=…`、またはトークンだけ): 確認シートで中身を見て保存。
- **レシピサイトのURL**: サーバーがページを1回取得し、`schema.org` の Recipe(JSON-LD)を読む。ログイン中のみ。
- **テキスト**(`【材料】`・`【作り方】`の見出しつき。SNSの投稿など): 見出しで区切って読む。ログイン中のみ。
- URL・テキストの取り込みは、**編集シートに下書きとして入る**。グラム数を読み取れなかった食材(「大さじ1」「1個」など)は**空欄**になり、
  利用者が入れるまで保存できない(推測で栄養を出さない。このアプリの売りは栄養の正確性のため)。「少々・適量」は 0g(栄養に入れない)として読む。
  元の材料の表記は、編集シートの上に並べて表示される。

## 公開手順(ブラウザだけで完了)

1. **先に D1 にテーブルを足す**: Cloudflare → Workers & Pages → D1 → `recipe-app-db` → コンソール に
   `db/migration-010-photos-shares.sql` の中身を貼り付けて実行(何度実行しても安全)。
2. GitHub でこのブランチのPRをマージ(Cloudflare Pages が自動でデプロイ)。
- 順番を逆にしても壊れません。テーブルが無い間は、保存済み一覧・削除は今までどおり動き、写真・共有のAPIだけが「データベースの更新が必要」と返します。
- `wrangler.toml` や環境変数の追加はありません。

## 仕様メモ

- 写真: 端末で長辺960px・約380KB以下のJPEGに縮小してから保存。サーバー上限は400KB(JPEG/PNG/WebPのみ。中身の先頭バイトも検査)。1レシピに1枚。
  ログイン中は D1(`recipe_photos`)、未ログインは端末の localStorage(ログインすると自動でサーバーへ引き継ぐ)。
- 共有: 1レシピ1リンク(推測できない32桁)。共有した時点のコピー(`recipe_shares.snapshot`)と写真を見せる。もう一度「共有」を押すと同じリンクの中身が更新される。
  含まれるのは料理名・材料・作り方・栄養・写真・取り込み元URLだけ(id・利用者名・メモ等は含まれない)。レシピを削除すると共有も消える。1人300件まで。
- 取り込んだ共有レシピは、新しいidの自分のレシピ(共有元とは別物)。
- 取り込みの安全策: ログイン必須・Origin確認。URLは `http(s)` のみ、IPアドレス・localhost・内部向けの名前・ポート指定・認証つきは拒否(リダイレクト先も検査)。
  取得は8秒・1.5MB・リダイレクト3回まで。
- 共有されたレシピは他人が作ったデータなので、サーバーで型を揃えて(数値は数値だけ)保存し、画面でもHTMLとして解釈しない。

## 課金ゼロの検証(外部AIが有料のため)

テストはすべて、実際のAI・外部サイトに接続しません。

- `node test/no-ai-cost_test.mjs` … 新機能のソースから import をたどって、AIを呼ぶファイルに届かないことを確認。AIのURL・キー・利用回数の記述が無いこと、
  サーバー側で `fetch` するのが「取り込みのページ取得」1か所だけであることも確認。
- `node test/media-api_test.mjs` / `node test/recipe-import_test.mjs` … D1の代わりにメモリ上のSQLite(`db/schema.sql` を実際に流す)で動かし、
  外部通信は見張り役(`test/_support.mjs`)が監視。x.ai への通信は即エラー、許可していない通信も即エラー。ページ取得は偽のサーバー応答。
- `node test/photo-share-import-ui_test.mjs` … ブラウザ(Playwright・iPhone幅)で画面を操作。全通信を横取りし、`/api/ai/`・`/api/admin/ai`・x.ai への通信と外部通信が0件であることを確認。

実行: `npm run test:media` / `npm run test:media-ui`(Playwright は `NODE_PATH` にグローバルの場所を指定)。

## 既知の限界

- URL取り込みは、ページに JSON-LD の Recipe がある場合だけ読める(多くの大手レシピサイトにあるが、サイトごとの対応は未確認。読めないときは「テキスト」へ)。
- InstagramなどSNSの投稿ページそのものは、ログインが必要なため取り込めない。投稿文をコピーして「テキスト」から取り込む。
- 取り込みでグラム数を自動で決めるのは「g・kg・ml・cc・L」と「少々・適量」だけ。大さじ・個・合は、食材ごとに重さが違うため空欄にしている。
- 実際のiPhone(Safari)での操作・本物のD1・本物のレシピサイトでの確認は、このテストの範囲外(下の手動確認を推奨)。

### 公開後の手動確認(5分)
1. 保存済みのレシピを開き、写真を追加 → タイルに出る
2. 「共有」→ リンクをコピー → 別のブラウザ(ログインなし)で開いて見られる/保存できる
3. 「共有をやめる」→ 同じリンクが「見つかりません」になる
4. 「取り込む」→ 好きなレシピサイトのURL(またはSNS投稿文のテキスト)
