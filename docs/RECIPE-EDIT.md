# レシピ編集・自作入力 設計書

作成日: 2026-10-02 / 状態: 実装済み

## 1. 目的とスコープ

保存済みレシピを自分で直せるようにし、AIを使わずに自作レシピも入力できるようにする。
栄養値は常にコード(日本食品標準成分表+`nutrition.js`)で計算する。AIは一切呼ばない。

### 対象
- 保存済みレシピの編集: 料理名・種類・食材(量の調整、入れ替え、追加、削除)・作り方
- 自作レシピの新規入力(編集と同じフォームを使う)
- 食材は「名前+グラム数」を入力し、自動で成分表に照合する
- 成分表に見つからない食材は、7指標を任意で手入力できる
- 保存は「上書き」と「別名で保存」を選べる(自作の新規入力は「保存」のみ)

### 対象外
- 計算内訳(`ingredientDetails`)を持たない古い保存済みレシピ(ユーザー配布前のため考慮しない)
- 未ログインでの編集(ログイン必須。未ログインは案内を表示)
- プレビュー計算の1ユーザー1日あたりの上限回数(今回は付けない。サイズ制限とデバウンスのみ)
- AIによる食材の補完・提案、週次プランとの連携

## 2. 決定事項(要件)

| 項目 | 決定 |
|---|---|
| 編集の対象 | 食材の量・差し替え・追加・削除、料理名、種類、作り方 |
| 食材の照合 | 名前+グラム数を入力すると自動照合(既存の `matchFood`)。候補の手動選択はしない |
| 照合失敗時 | エラーにしない。7指標(calories / protein / fat / salt / fiber / carbs / veg)を任意で手入力できる。手入力は計算内訳に「手入力」と表示 |
| 保存方法 | 上書き、または別名で保存。自作は保存のみ |
| 未ログイン | 編集・自作入力は使えない |
| 栄養の計算 | サーバー側のコードのみ。保存時にも必ずサーバーで再計算する |
| AI・課金 | 編集機能はAI・外部APIを呼ばない。検証でも外部には接続しない |

## 3. 画面

### 入口
- 「保存済み」タブの上部に「自作レシピを作る」ボタン
- 各保存済みカードを開いた中の、「このレシピを削除」の隣に「編集」ボタン
- 未ログイン時は両ボタンを無効にし、「ログインすると編集できます」と表示

### 編集フォーム(全画面シート)
1. 料理名(1〜60文字)と種類(自由入力20文字まで。既存の種類名を候補として表示)
2. 食材の行(最大30行)。1行は「食材名」「グラム数」。行の追加・削除ができる
- 各行に、自動照合の結果を計算内訳と同じ形で表示する(例: `→ にわとり 若どり むね 皮なし 生`)
- 照合できない行(グラム数が0より大きいもの)には「該当なし」と表示し、「栄養値を手入力」を開くと7指標の入力欄が出る
3. 作り方(最大30ステップ。1行1ステップ。追加・削除)
4. 栄養の合計(プレビュー。常に表示)
5. 保存ボタン: 「上書き保存」「別名で保存」(自作の新規入力は「保存」のみ)

### プレビュー計算のタイミング
- 食材名・グラム数・手入力値の変化が止まって約0.8秒後に `POST /api/recipes/calc` を呼ぶ
- 前回計算した内容と同じ場合は呼ばない
- 計算中は合計を薄く表示し、返ってきたら更新する
- 最新の入力に対する計算結果がそろっているときだけ、保存ボタンを押せる

### 閉じるとき
未保存の変更があれば「変更を破棄しますか?」と確認する。

## 4. データ

保存するレシピの形は既存のまま(`name` / `type` / `ingredients` / `steps` / `ingredientDetails` / `nutrition` / `nutritionCheck` と各指標)。変更点は次の3つ。

- 編集した食材の行は `ingredientDetails` に `{ name, amount, grams }` で入れる。`amount` は `"250g"` の形。`ingredients`(文字列の配列)は `"キャベツ 250g"` の形でここから組み立てる。
- 手入力した栄養値は、その行に `manual: { calories?, protein?, fat?, salt?, fiber?, carbs?, veg? }` として持たせる。入力した指標だけが計算に入る。
- 編集・自作のレシピは、7指標すべてを `dish[id]` にも入れる(AI生成は生成時に選んだ指標だけ)。
- AI生成のレシピの行が持つ `food`(成分表風の表記)は、編集で行の名前が元のままの間だけ照合の手がかりとして送り直し、保存する行にも残す。名前を変えた行・追加した行には付けない。これは照合の手がかりの再利用で、手動の候補選びではない。

### 手入力の扱い
- `manual` は、グラム数が0より大きく、成分表に照合できなかった行にだけ使う。名前を直して照合できるようになった行の `manual` は、サーバーが捨てる。
- `manual` の値は、その行のグラム数ぶんの合計値(100gあたりではない)。
- `manual` の各値は0〜100000の数値。`veg` は「野菜として数える重さ(g)」。
- 手入力した行で、入力しなかった指標は0として計算し、その食材を `nutritionCheck.missing` に入れる(既存の「値のない項目は0として計算」の警告と同じ扱い)。

### 既存コードの変更
`nutrition.js` の `attachNutrition` を拡張する。照合できなかった行に `manual` があり、グラム数が0より大きいときは、`manual` の値を合計に足し、`ing.match = { foodNo: null, label: "手入力", manual: true }` を入れる。この行は `unmatched` に入れない。それ以外の計算は変えない。計算内訳の表示(`renderNutritionDetail`)は `ing.match.label` を出すだけなので、「手入力」と表示される。

## 5. API(すべてログイン必須。未ログインは401)

状態を変えるリクエストと `calc` は、既存の `checkOrigin` で Origin を確認する。

| API | 役割 |
|---|---|
| `POST /api/recipes/calc` | プレビュー用。保存しない。リクエスト: `{ ingredients: [{ name, grams, manual? }] }`。レスポンス: `{ ingredientDetails, nutrition, nutritionCheck }` |
| `PUT /api/recipes/:id` | 上書き保存。リクエスト: `{ name, type, ingredients: [{ name, grams, manual? }], steps: [] }`。サーバーで再計算して保存し、`{ recipe }` を返す。自分のレシピでなければ404 |
| `POST /api/recipes/custom` | 別名保存と自作の新規保存。リクエストは `PUT` と同じ。サーバーが `id` を付け、再計算して保存し、`{ recipe }` を返す |

- 既存の `POST /api/recipes` は、AI生成レシピの保存用として変更しない。編集・自作の保存では使わない(クライアントから届いた栄養値をそのまま保存しないため)。保存される栄養値は、必ずサーバーのコードによる計算結果になる。
- `recalcRecipe(env, 下書き)` を新しい共通関数(`functions/_lib/recipe-edit.js`)として作り、3つのAPIで共有する。入力の検査、成分表への照合、栄養の合計までを担当し、AIは呼ばない。

### 入力の上限(サーバーで検査。超えたら400と、どの欄かを返す)
- 料理名: 1〜60文字 / 種類: 20文字まで
- 食材: 1〜30行。名前は1〜40文字。グラム数は0〜5000の数値(0は計算対象外。水など)
- 作り方: 1〜30ステップ。各1〜300文字(空のステップは取り除く)
- 手入力: 上記の7指標だけ。各0〜100000の数値

## 6. エラー処理

| 状況 | 画面の動き |
|---|---|
| プレビュー計算が失敗 | 合計を薄く表示し「計算できませんでした」+再試行ボタン。保存は押せない |
| 入力が不正(400) | その欄の下に赤字で表示 |
| セッション切れ(401) | 「ログインが切れました。ログインし直してください」。フォームの内容は残す |
| 上書き先がない(404) | 「元のレシピが見つかりません」+「別名で保存」を案内 |
| 食材が成分表にない | エラーにしない。「該当なし」+手入力の案内。手入力なしでも保存できる(「計算に含まれていません」の警告が付く) |
| 保存の失敗 | シートを閉じず内容を残して、エラーを表示。再保存できる |

- 保存が成功するまで、`savedCache` は書き換えない。成功したら、サーバーが返した再計算後のレシピで置き換える。
- 失敗は `logError`(管理者向けエラーログ)に、`edit-calc` と `edit-save` の手順名で記録する。

## 7. 課金・負荷への配慮

- 編集・自作・プレビュー計算は、D1(成分表とレシピ)の読み書きだけで動く。AIも、その他の外部APIも呼ばない。
- プレビュー計算は入力が止まって約0.8秒後にだけ呼び、同じ内容は再計算しない。入力サイズはサーバーで制限する(第5章)。
- 成分表の食品名の読み込みは、既存の10分間のメモリキャッシュ(`loadFoodIndex`)をそのまま使う。
- 計算の回数制限は付けない(判断済み)。Cloudflare側のプラン(無料か有料か)は、管理画面で確認する。有料プランの場合は、D1の読み取り・書き込みが従量課金の対象になる。

## 8. テスト(通信はすべてスタブ。AI・本番には一切つながない)

1. `recalcRecipe` の単体テスト: 照合、手入力の合計、上限超過の400。手計算の値と一致すること。
2. APIのテスト: 401 / 400 / 404、他人のレシピは404、`PUT` と `custom` がクライアントから届いた栄養値を無視してサーバーで再計算すること。
3. 画面のテスト: 計算の遅延と再計算の省略、保存ボタンの有効・無効、404のときの別名保存の案内。
4. 課金のガード: テスト用の `fetch` を、`/api/recipes` 以外のURL(`api.x.ai` を含む)で即エラーにする。編集機能がAIを1回も呼ばないことを確認する。
5. 回帰: 既存テスト(`job_test` など)がそのまま通ること。
6. `package.json` に `test:edit` を追加する。本番へのデプロイや `wrangler ... --remote` は検証で使わない。
